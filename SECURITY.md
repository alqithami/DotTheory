# Security and Misuse Reporting

The included simulators and theory materials are intended for research, methodological development, and synthetic validation design. They should not be used for surveillance, reputational scoring of real people, covert influence, or consequential decisions about people.

## What to report

Please report:

- software vulnerabilities in repository scripts;
- privacy or re-identification risks in proposed data workflows;
- misuse scenarios involving reputational scoring, surveillance, or covert influence;
- errors in documentation that could encourage overclaiming or unsafe deployment;
- security issues in generated experiment outputs, logs, or repository automation.

## How to report

Until a private maintainer contact is added, open a GitHub issue with the label `security`, `misuse`, or `governance` when the report can be public.

If the report should not be public, contact the repository maintainer through the GitHub account associated with this repository and request a private reporting channel before disclosing sensitive details.

## Scope

This policy covers the repository scripts, documentation, experiment scaffolding, and manuscript-adjacent materials. It does not imply that the repository is suitable for operational deployment. The simulator is a research prototype and should not be used for decisions affecting real individuals or groups.

## Maintainer action

For valid reports, maintainers should:

1. acknowledge the issue;
2. assess whether the issue is a software vulnerability, misuse risk, documentation risk, or publication-governance issue;
3. patch code or documentation where appropriate;
4. record material changes in the repository history;
5. avoid publishing sensitive details until the issue is addressed.
