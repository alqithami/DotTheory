# Experiment 1: Dot-field prediction lift

This document specifies the first reproducible computational experiment for the Dot-Trace Theory repository.

The experiment is synthetic. It is not external empirical validation. Its purpose is to test whether the reference simulator exhibits the theoretical validation signature predicted by the theory: when agents are memory-sensitive and actions depend on retrieved social traces, a dot-field representation should improve held-out prediction relative to reduced agent-edge and flat-memory baselines.

## Research question

Does explicit dot-field information improve held-out prediction of future cooperation in a synthetic social-memory system?

The action outcome is:

\[
Y_{t+1}=1
\]

when an actor cooperates with a target agent, and

\[
Y_{t+1}=0
\]

otherwise.

The main comparison is between a reduced baseline and a full dot-field predictor. The expected validation signature is positive held-out log-loss lift:

\[
\widehat{PL}^{LL}_{D\mid C}=\widehat R_C^{test}-\widehat R_D^{test}>0,
\]

where \(C\) is a reduced comparator such as an edge-only, private-memory, or bag-of-dots model.

## Interpretation rule

A positive result should be interpreted as a synthetic mechanism check, not as proof that the theory is empirically true in real-world social systems.

A disciplined interpretation is:

> In a controlled synthetic system where behavior is generated by retrieved trace pressure, the full dot-field representation provides held-out predictive information not present in reduced baselines.

A disciplined non-interpretation is:

> Dot-Trace Theory has been validated in real social systems.

The latter requires external data, measurement validation, and causal identification.

## Baselines

The trainable validation runner fits the following predictors on a temporal training split and evaluates them on held-out future records.

| Model | Feature family | Purpose |
|---|---|---|
| `b0` | Intercept only | Unconditional baseline |
| `edge` | Trust edge | Reduced social-network baseline |
| `private_flat` | Trust plus private pressure | Private-memory baseline |
| `bag` | Trust, bag pressure, accessible target count | Access-aware but retrieval-poor baseline |
| `full` | Trust, retrieved dot pressure, retrieved count, accessible target count | Full dot-field predictor |

The full model is compared against the reduced baselines through paired log-loss lift.

## Negative controls

The experiment also evaluates corrupted dot-field features. These controls preserve some marginal information while disrupting theoretically meaningful alignment.

| Control | Corruption | Expected signature |
|---|---|---|
| `control_pressure_shuffle` | Shuffles retrieved pressure | Lower performance than aligned full model |
| `control_access_shuffle` | Shuffles access/retrieval counts | Lower performance than aligned full model |
| `control_temporal_reverse` | Reverses dot pressure within each run | Lower performance if timing matters |
| `control_target_shuffle` | Shuffles target-specific pressure at each time | Lower performance if target binding matters |

The negative-control metric is log-loss degradation relative to the aligned full dot-field model:

\[
\widehat{NCD}^{LL}_{q}=\widehat R^{test}_{D,q}-\widehat R^{test}_{D}.
\]

Positive values indicate that the corrupted dot-field features performed worse than the aligned full dot-field features.

## Mechanism ablations

The orchestration script runs a full condition and four ablated conditions by default.

| Condition | Removed mechanism |
|---|---|
| `full` | None |
| `no_transmission` | Dot transmission across agents |
| `no_topology_feedback` | Dot-responsive social-edge updates |
| `no_mutation` | Dot mutation during transmission |
| `no_correction` | Counter-dot correction process |

Ablations do not prove that a mechanism exists in external data. They show whether the simulator's validation signature depends on that mechanism under the configured synthetic process.

## Run commands

Quick local run:

```bash
make experiment-01-quick
```

Full configured run:

```bash
make experiment-01
```

Manual run:

```bash
python scripts/run_experiment_01_prediction_lift.py \
  --config configs/experiment_01_prediction_lift.json \
  --out results/experiment_01
```

Dry run, useful for checking command construction without executing all conditions:

```bash
make experiment-01-dry-run
```

## Reporting cautions

When reporting Experiment 1, state explicitly that:

1. the experiment is synthetic;
2. the simulator generates the data-generating process;
3. the results are mechanism checks, not external validation;
4. positive prediction lift supports operational coherence of the formal model under controlled assumptions;
5. real-data validation requires dot extraction, observability assessment, negative controls, and causal identification.

## Minimal acceptable result

The strongest useful pattern is:

1. positive lift of `full` over `edge`;
2. positive lift of `full` over `bag`;
3. degradation under at least one negative control;
4. reduced or altered lift under at least one mechanism ablation;
5. stable direction across more than one seed.

If these conditions are not met, the paper should report the result honestly and treat it as a simulator-design or parameterization issue rather than as evidence against or for the theory in external systems.
